# Протокол замеров: чанкинг и качество поиска (практика 2)

## Исходные данные

Корпус: `data/raw/rules.pdf` — правила приёма в вуз, PDF, N страниц.

## Словарь рубрик

| Рубрика | По какому правилу присваивается |
| --- | --- |
| admission | по имени файла `rules` или по ключевым словам: приём, прием, поступление, заявление, документ, срок |
| dormitory | по ключевым словам: общежитие, заселение, проживание, комната, койка |
| cost | по ключевым словам: стоимость, оплата, плата, обучение, скидка, приказ |
| exams | по ключевым словам: экзамен, испытание, ЕГЭ, балл, вступительный |
| general (по умолчанию) | всё, что не распознано ни одним правилом выше |

## Замеры

| № | CHUNK_SIZE | CHUNK_OVERLAP | Чанков в индексе | hit-rate@5 | hit-rate@1 |
| - | ---------- | ------------- | ---------------- | ---------- | ---------- |
| 1 | 256 | 64 | 499 | 100% | 100% |
| 2 | 512 | 64 | 220 | 100% | 100% |

> Колонка `hit-rate@1` заполнена, потому что `hit-rate@5` одинаков во всех прогонах:
> на малом корпусе он упирается в потолок и варианты не различает (§2.6 задания).
> Замер: `from ingest import evaluate_retrieval; evaluate_retrieval(k=1)`.

**Выбранные значения и основание.**

Приняты CHUNK_SIZE = 512, CHUNK_OVERLAP = 64. Показатели hit-rate@5 и hit-rate@1
одинаковы (100%) в обоих прогонах: корпус состоит из одного файла, поэтому
правильный источник находится при любой нарезке. Показатель не различает варианты.
Выбор сделан по вторичному показателю — числу чанков в индексе: при равном
качестве поиска меньшее число чанков предпочтительнее, так как индекс компактнее
и в выдачу реже попадают два фрагмента одной и той же мысли.
