# Протокол замеров: чанкинг и качество поиска (практика 2)

## Исходные данные

Корпус: `data/raw/rules.pdf` — правила приёма в МГУ, PDF, 38 страниц.
Файл корпуса отслеживается git: строки `data/raw/*` и `!data/raw/README.md`
из `.gitignore` удалены.

## Словарь рубрик

| Рубрика | По какому правилу присваивается |
| --- | --- |
| dormitory | по ключевым словам: общежитие, заселение, проживание, койка, комендант, быт |
| exams | по ключевым словам: экзамен, испытание, ЕГЭ, балл, вступительный, предмет, профильный, минимальный |
| cost | по ключевым словам: стоимость, оплата, скидка, тариф, рубль, платный, цена, платёж |
| admission | по ключевым словам: приём, поступление, заявление, подача, направление, бюджет, целевой, абитуриент, комиссия, документ, срок, согласие |
| general (по умолчанию) | всё, что не распознано ни одним правилом выше |

Частные рубрики проверяются раньше `admission`: иначе общее слово «документ»
перекрывает более точную рубрику, и фильтр роли перестаёт работать.

## Замеры

| № | CHUNK_SIZE | CHUNK_OVERLAP | Чанков в индексе | hit-rate@5 | hit-rate@1 |
| - | ---------- | ------------- | ---------------- | ---------- | ---------- |
| 1 | 256 | 64 | 500 | 100% | 100% |
| 2 | 512 | 64 | 221 | 100% | 100% |

> Замеры сняты после исправления очистки: числа в тексте (сроки, баллы,
> количества) больше не удаляются. `hit-rate@5` и `hit-rate@1` во всех прогонах
> равны 100%, потому что корпус состоит из одного файла `rules.pdf`: любой
> непустой результат поиска принадлежит этому файлу. На таком корпусе метрика
> упирается в потолок и варианты нарезки не различает.

**Выбранные значения и основание.**

Приняты `CHUNK_SIZE = 512`, `CHUNK_OVERLAP = 64`. Качество поиска на обоих
прогонах одинаково (100% и по `hit-rate@5`, и по `hit-rate@1`), поэтому выбор
сделан по вторичному показателю — числу чанков: 221 против 500. При равном
качестве меньший индекс предпочтительнее: он компактнее, и в выдачу реже
попадают два фрагмента одной и той же мысли.

## Проверка фильтрации

После сборки индекса фильтр по рубрике возвращает только эту рубрику. Запрос
`where={"category": "dormitory"}` вернул пять фрагментов, у всех категория
`dormitory`. Фрагментов без категории нет. Распределение по индексу:

| Рубрика | Чанков |
| --- | --- |
| exams | 90 |
| admission | 86 |
| general | 18 |
| cost | 17 |
| dormitory | 10 |

## Уточнение метрики из технического задания

На практике 1 для поиска релевантных фрагментов объявлено целевое значение
`≥ 0,80`. Первый замер на практике 2 дал 100% на четырёх вопросах с
`expected_sources` (`out_of_scope` в замер не входит).

Цель оставлена `≥ 0,80`, а не поднята до 100%: корпус состоит из одного файла,
а вопросов в замере четыре. При такой шкале 100% — это потолок метрики, а не
доказательство качества поиска на живых вопросах. Уточнение сделано по
результату практики 2 и зафиксировано в `README.md`.
